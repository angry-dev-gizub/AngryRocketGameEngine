# DD-005: Shared Error and Result API Across Layers

**Date:** 26-11-2026  
**Status:** Accepted  
**Area:** Error System / Architecture

## Context

Previously, PAL and Core were intended to maintain separate error-handling mechanisms because they were designed as independent libraries.

With PAL becoming part of Core, maintaining separate error representations and Result APIs is no longer necessary.

Additionally, Runtime requires error handling while maintaining a consistent interface with the lower-level components.

## Decision

Angry Rocket will use one common error representation and Result API across its architectural layers.

The common Error and Result API will be owned by Core.

Platform functionality and other Core components will use this API to report operation outcomes.

Runtime will also use the common Error and Result API rather than introducing a separate error representation or Result type.

Runtime may implement its own error-management facilities, including:

- Error logging.
- Error reporting.
- Error propagation.
- Error filtering.
- Diagnostic information.
- Error handling policies.

These facilities do not introduce a separate error representation.

The Result API will distinguish operation success from failure independently of error severity.

## Consequences

- All architectural layers use a consistent error representation.
- Error propagation between layers becomes simpler.
- Duplicate Result implementations are avoided.
- Runtime can provide specialized error-management functionality without fragmenting the error system.
- Core owns the common error and Result contracts.
- Higher-level components remain free to implement their own error-handling policies.

## Alternatives Considered

### Separate Result APIs for Core and Runtime

Rejected because separate implementations would introduce unnecessary complexity and make error propagation between layers more difficult.

### A completely independent Runtime error representation

Rejected because Runtime should integrate with the common error system rather than introduce another incompatible representation.
