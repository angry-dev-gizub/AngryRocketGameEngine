# DD-002: 64-Bit Packed Error Representation

**Date:** 26-11-2026  
**Status:** Accepted  
**Area:** Error System

## Context

The previous error representation used a 32-bit integer containing three fields:

- Severity
- Domain
- Code

With the evolution of Angry Rocket's architecture, additional information is required to identify errors more precisely.

In particular, the error representation needs to identify the architectural layer where an error originated and the source of its error code.

A larger representation is therefore necessary.

## Decision

Errors will be represented using a packed 64-bit unsigned integer (`uint64_t`).

The representation consists of five fields:

| Field | Size |
|---|---:|
| Layer | 8 bits |
| Severity | 8 bits |
| Domain | 8 bits |
| Source | 8 bits |
| Code | 32 bits |
| **Total** | **64 bits** |

The fields will be packed into a deterministic bit layout.

The implementation will use explicit bit shifts and masks rather than relying on C bit-field layout.

## Consequences

- Error information can be represented consistently across all engine layers.
- Native operating-system and external-library error codes can be preserved.
- The representation provides sufficient space for future error definitions.
- Error construction and extraction require clearly defined operations.
- The packed representation must remain consistent across supported compilers and architectures.

## Alternatives Considered

### Retaining the 32-bit representation

Rejected because the existing representation does not provide sufficient space for the additional information.

### Using a structure with separate fields

Rejected in favor of a compact, deterministic integer representation.
