# DD-001: Platform Abstraction Layer Independence

**Date:** 2026-11-24  
**Status:** Accepted  
**Area:** Architecture / Platform Abstraction Layer

## Context

The Platform Abstraction Layer (PAL) and Core Layer are designed as separate libraries with different responsibilities.

PAL provides abstractions for interacting with operating-system resources. Core provides general-purpose infrastructure such as containers, algorithms, data structures, and its own memory allocation facilities.

Core needs to use functionality provided by PAL. However, PAL must not depend on Core, since that would introduce a circular dependency between the libraries.

PAL must also be reusable independently of Angry Rocket Core. Other libraries and applications should be able to use PAL without adopting Angry Rocket's Core Layer or any particular Core implementation.

## Decision

The Platform Abstraction Layer must remain completely independent of the Core Layer.

PAL must not include, link against, or require functionality provided by Angry Rocket Core.

PAL must be independently usable by other libraries and applications, regardless of whether they use Angry Rocket Core, another core library, or no core library at all.

PAL may provide its own abstractions and facilities where needed, provided that they do not introduce a dependency on Core.

## Consequences

- Core can depend on PAL without creating a circular dependency.
- PAL can be built, tested, and reused independently of Angry Rocket Core.
- Applications and libraries can use PAL without adopting Angry Rocket Core.
- PAL must own and maintain any functionality it requires rather than relying on Core-specific facilities.
- Interfaces shared between PAL and Core must not require Core types or implementation details.

## Alternatives Considered

### Making PAL depend on Core

Rejected because Core already depends on PAL. This would create a circular dependency and prevent PAL from being used independently.

### Sharing Core facilities with PAL through a common dependency

Not selected. The goal is for PAL to remain independently reusable, rather than requiring a separate shared library solely to support the dependency relationship.
