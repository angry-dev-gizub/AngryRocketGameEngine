# DD-003: Independent Allocator Abstractions in PAL and Core

**Date:** 2026-11-24  
**Status:** Accepted  
**Area:** Architecture / Memory Management / Platform Abstraction Layer / Core

## Context

Both the Platform Abstraction Layer (PAL) and Core may need dynamic memory allocation.

Core provides a general-purpose allocator abstraction for its own functionality and for use by higher-level systems.

However, PAL must remain independent of Core. Using the Core allocator inside PAL would introduce a dependency from PAL to Core, contradicting the architectural requirement that PAL be independently reusable.

At the same time, PAL may benefit from an allocator interface of its own rather than exposing its internal allocation strategy or relying directly on a particular external allocator.

## Decision

PAL and Core will each provide and own a separate allocator abstraction.

The PAL allocator is part of PAL and must not depend on the Core allocator or any other Core functionality.

The Core allocator is part of Core and may be used by Core and higher-level systems according to the Core allocator's interface and contracts.

The two allocator abstractions are independent. They may have similar purposes, but neither is required to use, wrap, or depend on the other.

## Consequences

- PAL can manage its allocation requirements without depending on Core.
- Core retains control over its own allocator interface and allocation strategies.
- Both libraries can be built and reused independently.
- Allocator types and contracts remain owned by the library that defines them.
- Memory allocated through one allocator abstraction must be released through the corresponding allocation interface; the two allocator domains must not be mixed.

## Alternatives Considered

### Using the Core allocator inside PAL

Rejected because it would introduce a dependency from PAL to Core and violate PAL's independence.

### Using only the C standard library allocation functions in PAL

Not selected. A PAL-owned allocator abstraction provides a defined interface for PAL's allocation needs without coupling PAL to Core or exposing a fixed allocation strategy to its users.
