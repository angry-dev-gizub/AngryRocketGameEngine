# DD-004: Packed Error Representation

**Date:** 2026-11-24  
**Status:** Superseded  
**Superseded By:** [26-11-2026/DD-002: 64-Bit Packed Error Representation](../26-11-2026/DD-002.md)  
**Area:** Architecture / Error Handling

### Context

The engine requires a common representation for errors that can be returned by different subsystems.

Using plain integer error codes would make it difficult to distinguish errors belonging to different domains and to classify their severity.

The error representation should allow an error to be stored and passed around as a single value while retaining its classification information.

### Decision

Errors are represented as a single packed `uint32_t` integer.

The packed representation contains three fields:

- Severity: 8 bits
- Domain: 8 bits
- Code: 8 bits

The numeric layout is `0x00SSDDCC`, where:

- `SS` represents the error severity.
- `DD` represents the error domain.
- `CC` represents the error code within that domain.

The upper 8 bits are reserved.

An error is therefore represented by one integer containing all three fields.

### Consequences

- Errors can be passed and stored as a single integer.
- Error classification does not require additional structures.
- Error values have a consistent representation across subsystems.
- Individual fields can be extracted when required.
- The representation supports domain-local error codes.

### Alternatives Considered

**Using separate fields for severity, domain, and code**

Rejected because it would require a larger representation and additional handling when passing errors between functions.

**Using an unstructured integer error code**

Rejected because it would not provide a standardized way to identify the error domain and severity.
