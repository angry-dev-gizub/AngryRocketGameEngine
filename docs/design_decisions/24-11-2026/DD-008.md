# DD-008: PAL Error Reporting

**Date:** 24-11-2026  
**Status:** Superseded  
**Superseded By:** [26-11-2026/DD-005: Shared Error and Result API Across Layers](../26-11-2026/DD-005.md)  
**Area:** Platform Abstraction Layer

## Context

The Platform Abstraction Layer (PAL) must be independently usable without depending on Angry Rocket Core.

PAL operations can fail for various reasons, such as unavailable system resources, invalid platform handles, filesystem errors, or unsupported operating-system functionality.

PAL therefore needs its own mechanism for reporting errors. Depending on Core's Result API would introduce an unwanted dependency between the two libraries.

## Decision

PAL defines and owns its own error representation.

PAL does not use or depend on Core's Result API.

PAL functions report errors through PAL-owned error codes. Functions that return additional data use output parameters, allowing the function's return value to represent the operation's outcome.

For example:

```c
ar_pal_error_t pal_file_open(
    pal_file_t* out_file,
    const pal_path_t* path
);
```
> This code snippet does not represent an accurate represention of the actual code and is attended to serve purely as an example.

The exact error representation, error categories, and error codes are defined by PAL.

## Consequences

- PAL can report platform-specific errors without depending on Core.
- PAL remains independently reusable.
- Core can use PAL without introducing a circular dependency.
- Runtime can interpret or translate PAL errors when integrating platform operations with higher-level engine functionality.
- PAL maintains control over its own error definitions and reporting conventions.

## Alternatives Considered

### Using Core's Result API

Rejected because PAL must not depend on Core.

### Returning only Boolean values

Rejected as the sole error-reporting mechanism because a Boolean does not provide enough information to distinguish different failure causes.

### Using a generic Result implementation in PAL

Rejected because PAL does not need to own a general-purpose Result abstraction. Its responsibility is to expose platform operations and report their outcomes.
